# Example Scene Workflow

How example scenes are built, verified and shipped in this project — and the traps that
cost real time the first time round.

Read this before building another example scene.

---

## Why scenes matter here

Scene coverage is the project's main defence against a class of bug that nothing else
catches: code that compiles cleanly, passes unit tests, and only misbehaves once a scene
actually runs. A null dereference after a `RequireComponent` is removed. A validation
routine that rejects a valid setup. A missing reference.

Several such bugs reached students before `SceneSmokeTests` existed. Every component in a
scene is watched by it; every component that is not, is not.

**Current coverage: 63 of 75 student-facing scripts.** Measure it with the script at the
bottom of this file — never by hand.

---

## The workflow

### 1. Write a builder, not a scene

Example scenes are **generated by editor scripts**, not hand-placed. Builders live in:

```
Assets/ProjectAssets/Dev/SceneBuilders/Editor/
```

That folder is outside `Assets/eventGameToolKit/`, so the robocopy sync never ships it —
only the scene it produces is shipped.

Generating rather than hand-placing means a scene can be rebuilt after a component changes,
diffs are explainable, and the intent is in source rather than in a binary asset.

Each builder is a static class with a `[MenuItem("EGTK/Rebuild …")]` entry point.

### 2. Run it

```bash
unity command run_script --timeout 200 \
  --file "Assets/ProjectAssets/Dev/SceneBuilders/Editor/BuildXScene.cs" \
  --entry "BuildXScene.Build"
```

Check the console afterwards — the builders warn rather than throw when a serialized field
is missing, so a "success" result can still hide a misconfigured station:

```bash
unity command get_console_logs
```

### 3. Register it in Build Settings

```bash
unity command add_scene_to_build --path "Assets/eventGameToolKit/ExampleScenes/X.unity" --enabled true
```

**This is what puts the scene under the smoke test.** `SceneSmokeTests` reads its scene
list from Build Settings, so a scene that is not registered is not tested. Forgetting this
is silent.

### 4. Verify

```bash
unity command recompile && unity command recompile_status
unity command run_tests                                 # EditMode
unity command run_tests --mode playmode --async_tests   # then poll test_status
```

### 5. Ship it

```bash
cmd //c robocopy "…\gameToolKit\Assets\eventGameToolKit" "…\eventGameToolKit-Package" //MIR //XD .git //XF STATE.md
```

`//XF STATE.md` is required — the package repo has its own `STATE.md` that a plain `/MIR`
would delete. Commit both repos and push them together.

## Traps

Each of these cost real debugging time.

### UnityEvent fields are null after AddComponent

Unity populates serialized `UnityEvent` fields through the Inspector, not through
`AddComponent`. A builder that wires listeners straight after adding a component throws
`NullReferenceException`.

```csharp
var zone = go.AddComponent<InputTriggerZone>();
zone.onTriggerEnterEvent ??= new UnityEngine.Events.UnityEvent();   // required
UnityEditor.Events.UnityEventTools.AddVoidPersistentListener(
    zone.onTriggerEnterEvent, someComponent.SomeMethod);
```

Use **persistent** listeners, not `AddListener`. Persistent ones appear in the Inspector
exactly as a student would have dragged them in, which is the point of an example.

Variants: `AddVoidPersistentListener`, `AddIntPersistentListener`,
`AddStringPersistentListener`, `AddBoolPersistentListener`.

### Some components hold a list where each entry owns its own event

`ActionRandomEvent` and `ActionShuffleEvent` do not have one event on the component. They
hold an array of nested `[Serializable]` entries, each with its own `onSelected`. Build the
array by reflection, wire each entry, then assign:

```csharp
var weighted = new WeightedEvent[3];
weighted[i] = new WeightedEvent { label = "…", probability = 1f,
                                  onSelected = new UnityEngine.Events.UnityEvent() };
Wire(weighted[i].onSelected, toggles[i].Toggle);
typeof(ActionRandomEvent)
    .GetField("weightedEvents", BindingFlags.Instance | BindingFlags.NonPublic)
    .SetValue(random, weighted);
```

### The two platform animators take different Waypoint structs

`PhysicsPlatformAnimator.Waypoint` has `transform`, `pauseTime` **and `normalizedTime`**.
`ActionPlatformAnimator.Waypoint` has only the first two. Setting `normalizedTime`
unconditionally throws. Check each field for null before assigning.

### Setting transform.position on an interpolated Rigidbody does nothing

The physics engine overwrites it on the next step. Use `rigidbody.position`. This silently
invalidated an entire verification pass — the object never moved and every measurement
taken afterwards was meaningless.

### AssetDatabase.MoveAsset, never the filesystem

Moving folders with `mv` orphans `.meta` files and breaks every scene reference. And do
**not** wrap moves in `StartAssetEditing`/`StopAssetEditing`: batching defers folder
registration, so freshly created folders do not exist yet as far as `MoveAsset` is
concerned and every move fails with "Parent directory is not in asset database".

### World-space TMP labels

The RectTransform is centred on the transform, so top-aligned text starts *above* where it
is placed and overlaps whatever is there. Set the pivot to the top:

```csharp
rt.pivot = new Vector2(0.5f, 1f);
rt.sizeDelta = new Vector2(width / 0.35f, 3.4f / 0.35f);
go.transform.localScale = Vector3.one * 0.35f;
tmp.fontSize = size / 0.35f * 2.4f;
```

Font: `Assets/TextMesh Pro/Resources/Fonts & Materials/LiberationSans SDF.asset`.

### Generate assets, do not borrow them

The only audio in the project lives in `ProjectAssets/ThirdParty/StarterAssets` and the only
animator controllers come from Unity samples. Referencing either from a shipped scene
repeats the packaging bug in CLAUDE.md § Known Issues.

`GenerateExampleAssets.cs` writes sound effects and an Animator Controller into
`ExampleScenes/GeneratedAssets/`, owned by the package. Extend it rather than reaching into
ThirdParty.

### eval quirks

- Needs `--timeout 60` or more; the first call pays a Roslyn cold start and a 5s budget
  fails with "Main thread operation timed out".
- Extension methods are invisible — the eval context has no `using` directives. Call them
  explicitly: `InputActionSetupExtensions.AddBinding(action, "<Keyboard>/f")`.
- Returning a value can report "unreachable code detected". `Debug.Log` and read the
  console instead.

### Python heredocs mangle `\n`

Writing C# string literals containing `\n` through a `python - <<'PY'` heredoc silently
produces real newlines and the match fails. Use `chr(92)+'n'`, or edit line by line.

## What cannot be verified from here

**Unity freezes play mode when the editor does not have focus.** Driving `editor_play` from
the command server leaves `Time.time` at `0.0` — nothing moves, and every sample reads a
frozen scene. Enabling `runInBackground` does not fix it.

This is separate from, and worse than, the main-thread stall: each command-server request
also stalls Unity's main thread, so the next `Time.deltaTime` absorbs the delay and drains
coyote timers, jump buffers and click state machines.

**Therefore:**

| To verify | Use |
|---|---|
| Does it compile | `recompile_status` |
| Does the scene load and run without errors | `SceneSmokeTests` |
| Frame-sensitive behaviour | A PlayMode test, inside Unity's own loop |
| Does it feel right / actually work | A human watching the Game view |

Do not attempt to confirm gameplay by sampling positions over `eval`. It produced a
confident, entirely false bug report once already.

## Remaining work: three scenes

12 scripts still have no example scene.

### 1. Decal scene (3D) — 4 components

`ActionBlinkDecal`, `ActionBlinkDecalOptimized`, `ActionDecalSequence`,
`ActionDecalSequenceLibrary`

URP decal projectors, so this must be a 3D scene with a surface to project onto. Needs a
decal material — generate one into `GeneratedAssets` rather than reusing anything from
ThirdParty. See `DecalAnimationSystem_Documentation.md` for how the sequence components
expect to be configured.

### 2. 3D physics scene — 4 components

`PhysicsForceZone`, `PhysicsBallPlayerController`, `PhysicsEnemyController`,
`CharacterPushRigidBody`

Their 2D counterparts are covered; these 3D originals are not. Two are full character
controllers, so this is closer to a small playable level than a station board. Follow
`BuildPlatformPairingScene.cs` for 3D setup — primitives, URP/Lit materials, a directional
light and a raised camera.

`CharacterPushRigidBody` is a companion to `CharacterControllerCC`, so it needs that
controller present to demonstrate.

### 3. Utility and puzzle scene — 4 components

`applicationFPSLimiting`, `StopMotionPostProcess`, `lockMouseCursorToDisplay`,
`PuzzleSequenceChecker`

These get their own scene because two of them are disruptive: `applicationFPSLimiting`
locks the whole game's framerate, and `lockMouseCursorToDisplay` confines the cursor.
Quarantining them means their side effects are expected rather than baffling. Label the
scene so the low framerate reads as deliberate.

`StopMotionPostProcess` needs an Animator — `GeneratedAssets/ExampleAnimator.controller`
already exists. `PuzzleSequenceChecker` needs a few `PuzzleSwitch` components to sequence.

## Measuring coverage

Run this from the project root. Never count by hand.

```python
import os,re,io
guid2name={}
for root,d,fs in os.walk('Assets/eventGameToolKit/Runtime'):
    for f in fs:
        if f.endswith('.cs.meta'):
            m=re.search(r'guid:\s*([0-9a-f]{32})',
                        io.open(os.path.join(root,f),encoding='utf-8',errors='replace').read())
            if m: guid2name[m.group(1)]=f[:-8]

# Internal helpers students never place in a scene
INTERNAL={'EGTKPhysics','EGTKInput','GameData','StopMotionJob','ISpawnPointProvider',
          'ITeleportableCharacter','DialogueUIController'}

used=set()
for base in ['Assets/eventGameToolKit/ExampleScenes','Assets/eventGameToolKit/Prefabs',
             'Assets/eventGameToolKit/Samples~','Assets/ProjectAssets/Scenes']:
    for root,d,fs in os.walk(base):
        for f in fs:
            if f.endswith('.unity') or f.endswith('.prefab'):
                for g in set(re.findall(r'guid:\s*([0-9a-f]{32})',
                        io.open(os.path.join(root,f),encoding='utf-8',errors='replace').read())):
                    if g in guid2name: used.add(guid2name[g])

student=sorted(n for n in guid2name.values() if n not in INTERNAL)
missing=[n for n in student if n not in used]
print(f"covered {len(student)-len(missing)}/{len(student)}")
for n in missing: print("  ",n)
```

The same GUID walk, made **transitive**, is what proves an asset is safe to delete. A direct
reference count is not enough: it reported `StarterAssets` and the Cinemachine `Samples` as
unused when package content reaches them through a material and two scenes.
